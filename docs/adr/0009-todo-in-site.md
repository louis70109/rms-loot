# ADR 0009：TODO 放進網站，資料只存在瀏覽器

- 狀態：已接受
- 日期：2026-11-24

## 背景

ADR 0002 決定了 TODO 怎麼連到攻略庫（只連結、用 slug、目錄有備援）。那時 TODO 是獨立的 HTML，後來發布成 Artifact（私人連結）。使用者希望它也在 rms-loot 網站裡，和其他分頁放在一起。

## 決定

1. TODO 是網站的一個分頁，路由是 `/todo`，模板在 `templates/todo.html`，腳本與樣式分別是 `static/todo.js`、`static/todo.css`。樣式限定在 `.todo` 底下，不影響其他頁面。
2. **資料只存在使用者自己的瀏覽器（localStorage）**，不寫入資料庫，也沒有新增任何 API。這表示 TODO 不需要資料表、不需要權限設計，也不會因為部署而遺失資料，但換瀏覽器就看不到。
3. 權限：有開 Discord 登入時，member 與 owner 都可以看與使用（TODO 是個人的，沒有寫入伺服器，所以不需要限制）；未登入者會被導向登入。
4. 攻略目錄的讀取順序與 ADR 0002 相同：即時抓 `https://rms-data.fly.dev/index.json` → 上次的快取 → 內建快照 `static/guide-index-snapshot.json`。在網站內不受 Artifact 沙盒的限制，所以即時抓取可以用。
5. 內建快照要在攻略庫改名或新增頁面後更新，更新方式是重新抓取 `index.json` 並覆寫該檔案。

## 考慮過的替代方案

- **存到資料庫**：可以跨裝置同步，但要設計帳號與寫入權限，超出目前需求（見 ADR 0002 的後續）。
- **保留為 Artifact**：不需要部署，但和網站分離，無法共用導覽列與登入。

## 後果

- 正面：沒有新增資料表，不改動資料庫結構；頁面純前端，風險小。
- 負面：資料只在單一瀏覽器，換裝置或清除網站資料就會消失。
- 注意：合併到 `main` 會觸發部署（ADR 0005）。
