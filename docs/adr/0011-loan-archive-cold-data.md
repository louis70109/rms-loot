# ADR 0011：借還紀錄封存為冷資料，預設不顯示

- 狀態：已接受
- 日期：2026-11-27

## 背景

借還紀錄越積越多，大多數已經歸還、不再需要天天看。但偶爾還是會想回頭查，所以不能刪除。

## 決定

1. **封存是一個旗標**：`loans.archived`（0 或 1）。不搬到另一張表或另一個檔案，資料仍然在同一個資料庫裡，只是預設不列出。
2. **預設列表只顯示進行中**（`archived = 0`）。「已封存」是獨立的檢視，需要時才打開，列表與圖片都只在那時才查詢。
3. **封存方式**：
   - 單筆：列表上的「封存」按鈕，或編輯頁的「封存這筆紀錄」。
   - 批次：「封存所有已歸還」，只會封存已勾選「已歸還」的紀錄。
4. **取消封存**：在已封存的檢視中按「取消封存」，或在編輯頁操作。
5. **權限**：只有 owner 能封存與取消封存，成員看不到這些按鈕，直接呼叫會得到 403。
6. **舊資料庫**：啟動時自動補上 `archived` 欄位，既有紀錄預設為未封存。

## 考慮過的替代方案

- **搬到另一個資料表或另一個資料庫檔**：冷資料真的分開，但要處理兩邊的查詢、備份與還原，現在的量還不需要。
- **直接刪除已歸還的紀錄**：不可逆，使用者想保留歷史，不採用。
- **匯出成 CSV 後從資料庫刪除**：要多一個匯出流程，而且之後要找回來還得匯入。

## 後果

- 正面：列表保持乾淨；封存是可逆的；不需要搬移資料或圖片，`/backup` 仍然包含全部紀錄。
- 負面：封存的紀錄仍佔用資料庫與 volume 的空間。如果之後空間真的不夠，要重新評估是否把圖片搬到其他地方（見 ADR 0006）。
- 注意：「已封存」檢視會載入圖片，所以要在畫面上打開時才會增加流量與時間。
