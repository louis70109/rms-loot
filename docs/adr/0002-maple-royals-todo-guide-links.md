# ADR 0002：Maple Royals TODO 如何連到攻略庫

- 狀態：已接受
- 日期：2026-11-22

## 背景

使用者想要一份 Maple Royals 的待辦清單，分成「練腳色」與「解任務」兩區，可以寫備註，也想連到攻略庫（https://rms-data.fly.dev/，「RMS 攻略庫」）裡對應的任務頁面。

攻略庫是另一個 session 在維護的獨立網站，有這些限制：

- 頁面內容以 XOR 加 Base64 編碼後嵌在 HTML 裡，並標記 `noindex`。這是混淆，不是保護，但我們不應該去解碼或爬取內容。
- 站上沒有任務完成狀態的端點，所以 TODO 無法知道攻略庫上的進度。
- 攻略庫的 session 後來發布了公開的 `https://rms-data.fly.dev/index.json`，格式是 `[{"slug","title","cat"}]`，只含這三個欄位，不含內文，回應帶 `Access-Control-Allow-Origin: *`。
- Claude Artifact 的沙盒會擋住頁面對外的 `fetch`，也不允許 `alert()`。

## 決定

1. **只連結，不爬取、不解碼**。TODO 只存攻略頁的 slug，連結由 slug 組出：`https://rms-data.fly.dev/#<slug>`。
2. **完成狀態只存在使用者自己的 TODO 裡**，不從攻略庫讀取。
3. **目錄的讀取順序**：每次開頁即時抓 `index.json`（10 秒逾時）→ 失敗時用上次的 localStorage 快取 → 再失敗時用內嵌的目錄副本，並標示副本日期。
4. **內嵌副本**是因為 Artifact 沙盒無法直接讀取外部網址。副本需要在攻略庫改名或新增頁面後重新發布，否則選單會過時。
5. **slug 失效的處理**：項目保留原本存的 slug，若目錄裡找不到，顯示「頁面已不存在（slug）」，不讓頁面壞掉。
6. **手動連結**作為備案，只接受 `http://` 或 `https://` 開頭，不符合時在頁面內顯示提示，不使用 `alert()`。
7. **資料存在每個瀏覽器的 localStorage**，不做帳號或雲端同步。
8. **發布方式**：以 Claude Artifact 發布為私人連結（只有擁有者能開），要分享給別人需要在 Artifact 的 Share 選單設定。

## 考慮過的替代方案

- **解碼並爬取攻略內容**：可以做到完整的任務清單，但內容是刻意編碼過的，而且擁有者沒有授權，所以不採用。
- **用 iframe 嵌入攻略庫**：Artifact 不允許嵌入其他網站，也不適合。
- **把 TODO 存到 rms-loot 的資料庫**：可以跨裝置同步，但需要帳號與權限設計，超出目前的需求，之後需要再另外決定。
- **只即時抓目錄，沒有備援**：沙盒會擋住抓取，頁面在 Artifact 裡就不能用，所以需要內嵌副本。

## 後果

- 正面：不依賴攻略庫的內部格式，也不會把使用者送去爬取別人的內容。目錄失效時頁面仍然可以用。
- 負面：Artifact 內嵌的目錄會過時，需要重新發布才會更新。完成狀態與備註只在單一瀏覽器裡，換裝置就看不到。
- 風險：攻略庫如果改了 slug（改名），舊的連結會失效，只能顯示「頁面已不存在」。索引的格式如果改變，TODO 會退回快取或內嵌副本。
- 後續：若需要跨裝置同步或讀取攻略庫的完成狀態，要先與攻略庫的維護者確認 API，並另開一份 ADR。
